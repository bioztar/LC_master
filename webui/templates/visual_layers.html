Where to actually SEE an agent workflow

You were missing visuals because the CLI shows none. There are 4 places to look. Use them together.

1 · Graph topology — the static "shape"

Answers: "What can my agent do, and how do nodes connect?"

  • Generated by graph.get_graph().draw_mermaid_png()
  • This dashboard renders it on the overview page.
  • Standalone HTML: graph.html
  • Regenerate: python -m scripts.render_graph

When to use: docs, code review, explaining the agent to a stakeholder.

2 · Per-run state timeline — "what path did this question take?"

Answers: "For thread X, what did each node read/write? Where did it pause? Can I rewind?"

  • Built from the checkpointer — every transition is saved to SQLite (or Postgres in prod).
  • This dashboard reads them on the thread page and shows a vertical timeline.
  • Time-travel: Rewind here button forks a new thread starting from any past checkpoint.
  • Code: graph.get_state_history(config) in webui/app.py.

When to use: debugging "why did my agent do X?", building HITL UIs, demoing rollback to interviewers.

3 · Langfuse — every LLM call, prompt, token cost, latency

Answers: "What exact prompt+context did the LLM see? What did it return? How much did it cost? Where's the bottleneck?"

{% if langfuse_enabled %}

Wired ✓ Open {{ langfuse_host }}. Each run creates a Langfuse trace tagged with the thread_id.

{% else %}

Not wired Sign up at cloud.langfuse.com (free tier), copy keys into .env:

LANGFUSE_PUBLIC_KEY=pk-lf-...
LANGFUSE_SECRET_KEY=sk-lf-...
LANGFUSE_HOST=https://cloud.langfuse.com

Restart dashboard, run a question, click into the trace in Langfuse — you'll see a flame-graph of every LLM/retrieval/tool call.

{% endif %}

When to use: production. Always.

4 · LangGraph Studio — official drag/drop debugger

Answers: "I want to step through my graph node-by-node in a real GUI without writing my own dashboard."

  • Install: pip install -U langgraph-cli langgraph-api
  • Run from project root: langgraph dev → opens browser to a hosted Studio session
  • Requires a langgraph.json manifest (see Studio docs).

Trade-off: better UI than what we built, but requires their hosted control plane (free tier exists). The custom Flask dashboard you're looking at has zero external deps and works offline.
